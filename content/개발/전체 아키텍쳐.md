# 인수인계
## 서버 전체 구성
- 메인서버 <-> LB서버 <-> 크롤러서버(현재 세개)
- 이미지 리사이징, 매일아침 6시 materialized view 리프레쉬 등은 람다로 이루어지며 람다 처리가 끝난 후에는 C-LB 서버에 요청을 함으로서 알림을 보내거나 db에 데이터를 넣는다. 현상황에서 lambda는 public ip를 가질 수 없기에 우회해서 사용하는것
- 서버로 요청이 들어올때 처리되는 플로우는 아래와 같아
    - 유저 요청 ↔ DNS서버 ↔ ec2 public ip ←(secure)→ 도커 컴포즈로 구동되고 있는 nginx ←(nonsecure)→fastapi 서버 ↔ RDS


## 접속

## 서버별 역할 및 구성
- 메인서버
    - 모든 메인 작업을 처리한다
    - 파일
        - renew.sh
            - 유저 ↔ nginx 사이에는 https 연결이 사용된다. 이에 대한 인증서 요청은 cron job으로 설정되어 매달 재발급이 자동으로 시도됨
        - logs
            - 프로덕션 서버, 테스트 서버에 대한 로그가 기록된다. debug.log는 모든 요청에 대한 간단한 기록, error.log는 예외 처리한 예외에 대한 로그, server_error.log 는 예외처리 하지 못한 예상치못한 버그들(슬랙 알람 발송)
        - 그 외 환경변수
    - docker-compose
        - nginx : 외부 요청 라우팅, CORS, rate limit 등 처리
        - backend : 메인 서버
        - backend-test : 테스트 서버
        - stemmer : 형태소 분석기
        - redis : 메인 서버 레디스
        - redis : 테스트 서버 레디스
        - redis-dispatcher : 레디스에 카테고리 데이터 초기 로드 하고 죽는 이미지
        - network : nginx-network만 외부에 노출되어 있음. 나머지는 직접접근 불가능(사실 되긴하는데 거의 불가능)
- C-LB
    - 메인서버에서 들어오는 크롤링 요청을 crawler서버로 분산시킨다
    - nginx.conf 참고
- C-Crawler
    - 이미지 업로드, 크롤링, (구)네이버크롤링, 구글 이미지 크롤링 등에 사용된다
    - 이곳의 로그도 메인서버와 같은 방식으로 관리됨
- lambda
    - 이미지 리사이징, materialized view(게시글 추천) 의 refresh 에 사용된다

## CI/CD
### 메인 서버
- github action + amazon ecr을 이용한다
- 아래에서 말하는 “배포” 는 docker-compose 를 이용한 배포(docker-compose up)를 말함
- test 서버에 푸시가 일어날 경우 CI/CD작동이 시작된다
    - (build phase) 지금까지의 코드 내용들을 도커 이미지로 만듦 (buildx 사용, 이미지 캐싱됨). 이후 AWS ECR 에 이미지 푸시
    - (deploy phase) 메인 서버에 ssh를 통해서 접근하며 test서버에 대한 배포를 시작한다. AWS ECR에서 이미지를 땡겨오고 배포. 이때 현재 버전을 .env 파일에 작성한다
    - github 의 secrets 를 보면 이때 사용되는 여러가지 환경변수들에 대한 설정들이 존재
- main 서버에 푸시가 일어날 경우
    - .env 파일에 적혀있는 이미지 버전을 test와 동일하게 맞추고 다시 배포한다

### 크롤러 서버
- CI 는 만들어져있으나 CD는 없음
- 메인에 푸시 하면 자동으로 빌드돼서 ECR에 올라감
- 이후 크롤러 서버에 하나하나 들어가서 아래 방식으로 배포하면 됨

```shell
aws ecr get-login-password --region ap-northeast-2 | docker login --username AWS --password-stdin 123456789012.dkr.ecr.ap-northeast-2.amazonaws.com/wherehaus-crawler

docker pull 123456789012.dkr.ecr.ap-northeast-2.amazonaws.com/wherehaus-crawler:{hash} &&
docker stop fastapi &&
docker rm fastapi &&
docker run -d --name fastapi --tty --network="host" \
-v ./logs/instagram_adder:/code/app/logs \
-v ./instagram_session:/code/app/instagram_session \
--env-file .env.dev \
123456789012.dkr.ecr.ap-northeast-2.amazonaws.com/wherehaus-crawler:{hash} \
uvicorn app.main:app --host 0.0.0.0 --port 80


```
해쉬는 ecr에서 확인

## 간단한 개발환경
- python 패키지, 버전 관리는 전부 rye 를 통해서 하고 있음
- 기존에 로컬에서 테스트 할때는 아래 명령어로 서버 실행시켰음

```shell
rye run uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload --env-file .env.local
```
- 이때, docker 등으로 db를 띄워줘야함. 

```yaml
# docker-compose build
version: '3.8'
volumes:
  local-postgis:

services:

  db:
    image: kartoza/postgis:15-3.4
    container_name: local_postgis
    volumes:
      - local-postgis:/var/lib/postgresql
    environment:
      # If you need to create multiple database you can add coma separated databases eg gis,data
      - POSTGRES_USER=postgres
      - POSTGRES_PASS=postgres
      # Add extensions you need to be enabled by default in the DB. Default are the five specified below
      - POSTGRES_MULTIPLE_EXTENSIONS=postgis,hstore,postgis_topology,postgis_raster,pgrouting
      - RUN_AS_ROOT=true
    ports:
      - "25432:5432"
    restart: on-failure
    healthcheck:
      test: "PGPASSWORD=postgres pg_isready -h 127.0.0.1 -U postgres"

```
이 yaml 파일로 DB 띄우면 됨
- db 형상관리는 alembic 사용함. DB 설치 후 alembic upgrade 해줘야됨
