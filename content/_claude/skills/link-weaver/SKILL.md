# Link Weaver

Obsidian의 강점은 노트 간 양방향 링크다. 새 글이 고립되지 않게 기존 글망에 엮어 넣는다.

## 절차

### 1. 대상 글 분석
- frontmatter 태그(`topic/*`)와 본문 첫 ~30줄에서 **고유명사·기술명·개념어** 추출
- 예: "FastAPI에서 Pydantic alias 사용 시…" → `FastAPI`, `Pydantic`, `alias`, `validation`

### 2. 후보 풀 좁히기

순차적으로 좁힌다 (전체 .md grep은 마지막 수단):

1. **같은 폴더 + 공통 태그 1개 이상**
2. **다른 폴더 + 공통 태그 2개 이상**
3. **태그는 다르지만 제목에 키워드 포함** (Glob으로 제목 매칭)

### 3. 매칭 점수 (간이)

각 후보 글에 대해:
- 공통 태그 수 × 2
- 본문에 등장한 키워드가 후보 제목에 포함되면 +3
- 후보 본문에도 같은 키워드 빈출이면 +1

상위 3개만 제안.

### 4. 삽입 위치

- 본문에서 해당 키워드가 처음 등장하는 문장에 `[[제목]]` 형태로 감싸기 후보 제시
- 같은 글 내에서 같은 링크는 첫 번째 등장에만 (vault CLAUDE.md 규칙)

### 5. 사용자 확인 필수

링크는 의미적 결합이라 자동 삽입 금지. 다음 형식으로 제안만:

```
링크 후보 (확인 부탁):
1. "fastapi layered architecture" — 본문 12행 "controller-service-repository 구조"
2. "pydantic alias with 상속 + fastapi" — 본문 4행 "alias"
3. "fastapi pytest 문제 해결 과정" — 본문 마지막 단락 "테스트"

승인하시면 적용합니다.
```

## 안티 패턴

- 모든 등장 키워드를 다 링크 (가독성 붕괴) — 글당 최대 3~5개
- 너무 일반적인 단어 링크 ("개발", "코드", "문제")
- 후보 글을 읽어보지도 않고 제목만으로 매칭 — 본문 첫 단락은 확인할 것

## 트리거

- 명시적: "링크 추천", "관련 글", "wikilink 보강"
- 암시적: `blog-organizer`가 글을 이동시킨 직후 자동 호출 (단, 사용자 confirm 전엔 삽입 X)
